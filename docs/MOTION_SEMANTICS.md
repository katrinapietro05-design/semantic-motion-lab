# Motion Semantics (Working Draft)

## Principle

Motion should encode a meaningful system event. It must not imply a state change, authority, certainty, or successful correction that the underlying record does not support.

## Proposed motion vocabulary

- **Enter:** a component becomes present in the current view.
- **Transition:** a recorded state changes.
- **Emphasis:** a relevant item is called out without changing its state.
- **Return:** a user or system returns to a prior view or state.
- **Alert:** a defined condition requires review.

## Accessibility and evidence

Provide reduced-motion behavior, a text alternative, and visible state labels. Bind each transition to an event identifier and preserve source and timestamp. Never use animation alone to communicate risk or a decision.
